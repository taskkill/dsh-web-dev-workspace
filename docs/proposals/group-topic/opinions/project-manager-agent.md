# 项目经理 Agent 意见（议题式讨论）

**① 与七阶段流水线的边界**：议题讨论只产出方案建议；方案落地仍走各自阶段的既有闸门，acceptance/approval 只能由 `pipeline_submit_stage` 与 Owner 面板决定。讨论与确认不改变阶段状态，不能替代、跳过或加速任何闸门；方案卡须标注所属阶段。

**② 汇总者的输入/输出契约**：输入=齐全的成员意见（≥6 份）+ `SESSION_GROUP.md` + Owner 议题与确认结论；输出=`plan.md`，必须含需求目标与边界、数据与阶段状态机、UI 结构、任务分解（每条带可直接转任务卡的验收标准）、风险与工作量、待 Owner 确认项。拒绝汇总：意见缺失或少于 2 份、议题要求绕过闸门/先实现后讨论、关键分歧未裁决。

**③ Owner 确认闸门与打回语义**：方案卡状态 草稿→待确认→已确认/已打回；确认与打回都写入群消息与任务记录（谁/何时/原话摘要）。打回须写原因与被退回条目，回到汇总修订态，不自动执行；确认前 Host 与工具层硬闸门禁止任何执行类投递。

**④ 风险**：汇总者乐观偏差、漏掉反对意见；方案卡越界承担实现责任；讨论被误当审批；议题膨胀拖长。缓解：逐条回应意见、单列分歧项、确认前零执行、限定意见字数。
