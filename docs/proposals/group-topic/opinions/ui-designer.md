# 群组议题流程 · UI 设计意见（opc-design）

**① 信息架构**
- 阶段条吸顶群组头下：「议题→讨论→方案→执行」4 步，当前高亮+`aria-current="step"`，已完成可回看，未解锁不可点。
- 方案卡置时间线尾部（要点/待办数/产物），不另开页。
- 确认/打回放**底部吸顶操作条**（composer 上方）：主按钮「确认并执行」，次按钮「打回」，间距 ≥16px；确认需二次确认并提示「将生成 N 张任务卡」，打回必填原因。

**② 状态矩阵**

| 阶段 | 阶段条 | 方案卡 | 主行动 |
|---|---|---|---|
| 待讨论 | 第1步高亮 | 隐藏 | 发起讨论 |
| 讨论中 | 第2步+轮次 | 隐藏 | 结束发言 |
| 待出方案 | 第3步高亮 | 骨架屏 | 催办/汇总 |
| 待你确认 | 第4步待办高亮 | 展开+待办预览 | 确认/打回 |
| 执行中 | 第4步+进度 | 折叠只读 | 查看任务板 |
| 已关闭 | 全步灰化+结果 | 只读存档 | 重新打开 |

**③ 窄屏与规范**：<900px 单栏；阶段条横滚或折叠「2/4 讨论中·展开」；360px 操作条吸底、按钮全宽 ≥44×44，打回另起一行。间距仅 4/8 倍数，正文 14/20 或 16/24；正文与阶段高亮对比 ≥4.5:1，禁用态不可仅靠透明度；阶段用图标+文案+颜色三重编码；焦点环 2px+offset 2px、≥3:1。

**④ 风险**：阶段语义与运行态（进行中/暂停/归档）重叠 → 阶段条只表议题、头部 chip 表运行态；3s 轮询致阶段跳变 → 骨架屏+乐观更新；D3 误确认代价高 → 二次确认+任务数预览+撤销窗；窄屏吸底条遮挡尾部 → 预留安全区；「已关闭/打回后」恢复路径未定义。
