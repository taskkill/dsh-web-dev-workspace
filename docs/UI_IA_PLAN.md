# UI 信息架构规划：工作台 + OPC/开发分离

> 状态：**P0–P4 + 全宽化已实施（v1.2.40）**。
> 与初版规划的差异：工作台不再放在侧栏，而是作为**主内容区的全宽页面**（卡片网格、最大 980px、窄屏单列），打开工作区时默认展示；侧栏只保留 文件 / 搜索 / 更多，保证 260px 宽度下不再拥挤。侧栏「更多」的「首页」组与命令面板可随时回到工作台，右上角 × 返回编辑器/欢迎页。
> 实施结果：侧栏默认落「工作台」；顶级 = 工作台 / 文件 / 搜索 / 更多；更多菜单按「项目」「开发」分组；每个工作区记住上次视图；有进行中项目时优先落工作台。
> 背景：侧栏已有 8 个视图（文件/搜索/待办/任务/验收/流水线/Git/记忆）+ 顶栏多个图标 + 底部终端；Owner 只有「提需求、审批、交付」三类动作，却要面对 8 个入口。

## 1. 现状问题

| 问题 | 表现 |
|---|---|
| 心智模型混排 | 「项目交付」（流水线/验收/待办）和「写代码」（文件/搜索/任务/Git/记忆）挤在同一排标签，按出现顺序而非使用频率排列 |
| 没有默认落点 | 打开就是「文件」，但 Owner 的起点是「这个项目现在到哪了、要我做什么」 |
| 入口过多 | 顶级 8 个视图；移动端底部栏放不下，溢出进「⋯」后流水线/验收更难找 |
| 信息分散 | 需求在流水线、验收在验收、交付在验收底部、开发进度在任务/Git——Owner 要来回切 |
| 动作不集中 | 待审批只出现在流水线横幅；待交付物只在验收底部；没有「现在该干嘛」的统一答案 |

## 2. 设计原则

1. **Owner-first**：第一眼回答「现在需要我做什么」。
2. **顶级入口 ≤ 4**：工作台 / 文件 / 搜索 / 更多。
3. **两个心智模型分开**：OPC（项目/交付）与开发（代码/工程）分组，不混排。
4. **聚合而非堆叠**：工作台把「项目状态 + 待办动作 + 验收 + 交付」收到一屏。
5. **不删能力**：原有视图全部保留，只是降级到二级入口；agent 工具与流水线状态不变。

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 双模式切换**（OPC / 开发） | 顶部切换，两套独立标签栏 | 最干净，两套体验各自完整 | 切模式有成本；agent 工作时 Owner 想看开发进度要切换 |
| **B. 单列重排** | 工作台置顶，低频视图收进更多 | 改动最小 | 8 个仍在一个层级里找，认知负担没真正下降 |
| **C. 工作台 + 分组「更多」**（推荐） | 顶级只留工作台/文件/搜索/更多；更多菜单按「项目」「开发」分组 | 默认落点清晰、顶级入口少、成本可控 | 流水线/验收需要两次点击（可接受，工作台已聚合关键动作） |

## 4. 推荐方案（C）：工作台 + 分组

### 4.1 顶部（桌面侧栏标签 / 移动端底栏）

```
[ 工作台 ]  [ 文件 ]  [ 搜索 ]  [ ⋯ ]
```

「⋯」弹出分组菜单（移动端为底部弹层）：

```
项目
  流水线      查看六阶段详情、启动/重发角色提示
  验收        清单、证据、审阅标记、报告/交付包
  待办        工作区任务板
开发
  任务        build/test 运行与输出、Problems
  Git         更改/暂存/提交/已审/回滚
  记忆        跨会话工作区记忆
Harness 信息   保持顶栏小图标，不占标签
```

### 4.2 工作台（Owner 首页）

```
┌ 工作台 ─────────────────────────────────────────────┐
│ 当前项目   <需求标题>                     [编辑]    │
│   ● 阶段 3/6 开发实现   进行中        [查看流水线]   │
│ ── 需要你处理 ───────────────────────────────────── │
│   ! 第 5 关「PM/客户确认」待审批   [通过] [打回]     │
│ ── 验收 ──────────────────────────────────────────  │
│   通过 4 · 未通过 1 · 待验收 2      [去验收]         │
│   ✗ 登录错误提示不可见 ······       [查看/发回 agent]│
│ ── 交付物 ─────────────────────────────────────────  │
│   [导出验收报告] [打包交付] [复制预览链接] [发布记录] │
│ ── 运行中 ─────────────────────────────────────────  │
│   dev server :5173 运行中 · 构建最后一次通过  [打开]  │
│ ── 最近活动（折叠） ───────────────────────────────  │
└─────────────────────────────────────────────────────┘
```

**区块优先级**（从上到下）：

1. **当前项目**：需求标题 + 当前阶段 + 进度；无项目时显示「说需求 → 开工」一行输入。
2. **需要你处理**：待审批（通过/打回）、被打回待重派、交付物可导出——这里没有内容时显示「暂无待办，团队进行中」。
3. **验收**：通过/未通过/待验收计数 + 未通过项列表（点击跳验收）。
4. **交付物**：报告、交付包、预览链接、发布记录（存在才显示）。
5. **运行中**：任务面板里正在跑的命令 + 端口 + 最近构建/测试结果。
6. **最近活动**（默认折叠）：阶段变更、验收回填、发布记录。

### 4.3 行为规则

- **默认落点**：工作区存在进行中的项目（pipeline 有需求且未完成）→ 工作台；否则文件。之后记住每个工作区上次停留的视图。
- **移动端**：底栏只保留 4 项；「⋯」为底部弹层，含分组。
- **空状态**：工作台无项目时只显示一个输入框 + 「开工」，不展示空卡片。
- **降级**：所有原视图仍可经「更多」或命令面板（`Ctrl/⌘+Shift+P`）一键打开。

## 5. 实施阶段与成本

| 阶段 | 内容 | 成本 |
|---|---|---|
| **P0** 工作台 v1 | 新视图：当前项目、待你处理（审批/导出）、验收摘要、交付物、运行中；复用现有 pipeline/acceptance/task 接口，只读 + 审批按钮 | 1–2 天 |
| **P1** 标签收拢 | 顶级改为 工作台/文件/搜索/更多；更多菜单按「项目/开发」分组；保留命令面板入口 | 0.5–1 天 |
| **P2** 默认落点与记忆 | 按「是否有进行中项目」决定默认视图，并记住每个工作区上次视图 | 0.5 天 |
| **P3** 工作台动作补齐 | 一键开工、发回未通过项、重跑失败任务、复制预览链接等直达动作 | 1 天 |
| **P4** 移动端 | 底部 4 项 + 分组弹层 + 安全区 | 0.5–1 天 |
| **P5**（可选） | 流水线+验收合并为「项目」子页；开发视图进一步收进设置 | 1–2 天 |

> 合计约 4–6 个工作日，可拆成 2–3 个验收批次；不改 Host 协议，只动 `client.js` 与文案。

## 6. 验收标准

- [ ] Owner 打开侧栏第一眼就知道「现在要做什么」，不需要记 8 个标签。
- [ ] 顶级入口 ≤4 个；移动端底栏 ≤5 项且无需横向挤压。
- [ ] 任意原视图 ≤2 次点击可达（更多菜单 / 命令面板）。
- [ ] 工作台一屏内可完成：看阶段、审批、看验收结论、导出交付物。
- [ ] 无项目时工作台是「一句话开工」空状态，不是空卡片。
- [ ] agent 侧工具与流水线行为不变（纯客户端信息架构调整）。
