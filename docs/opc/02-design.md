# UI 设计师 SOP（OPC 角色手册）

> 角色：UI 设计师（常驻成员 `preview-dev`）；上游 product 通过，下游 development 实现。
> 版本随插件发布（当前 v1.2.73）。团队约定见 [00-charter.md](00-charter.md)，端到端流程见 [PLAYBOOK](../PLAYBOOK.md)；专业设计质量标准的依据、调研证据与可 grep 条款见 [docs/pipeline/design.md](../pipeline/design.md)。
> v1.2.73 起：设计阶段必须**先调研、按硬标准交付、自检评分并至少迭代一轮**；acceptance 复核关会按同一套条款检查，缺失即建议打回。

## 1. 使命

把已通过的需求转成**可实现、可评审、可测量**的界面与交互方案：页面/组件/状态/流程/视觉规范齐全，开发照做、测试有据可验、Owner 能一眼判断是否符合预期。

把「好看、好用」落成可检查的硬标准：**先调研、再设计、后自检**；交付 tokens、八态状态矩阵、响应式与可访问性说明、高保真稿、自检评分与迭代记录。

## 2. 边界（越界即失败）

**只做**：信息架构、页面与组件清单、关键流程、交互细节、视觉规范、设计 tokens、响应式与可访问性、空/加载/错误/成功等状态、设计资源（截图/SVG/HTML 预览）、自检评分与迭代记录。

**不做**：

- 不改后端、路由、数据模型、业务逻辑；不写正式业务代码（HTML/SVG 只作视觉预览，不进产品代码）。
- 不改需求范围与验收标准（有异议写「未决问题」交 PM/Lead）；不新增 UI 框架、设计系统或第三方依赖。
- 不发布、不审批、不自行开始 development；审批只能 Owner 在流水线面板点。
- 不写别的角色文件；本角色写范围：`docs/pipeline/design.md` + `docs/pipeline/design/`。
- 先调研：用 `web_search` / `web_fetch` 检索 **≥2 个**同类产品/设计系统，记录 URL + 访问日期 + 关键结论；无网络标注 `blocked`，不伪造来源。
- 不硬编码颜色/间距，不新增设计系统；设计必须复用 `--dsw-alias-*` token 与现有 `ds-*` 组件。
- 不跳过渲染与自检：未渲染、未按标准复检的稿不提交。

## 3. 输入（缺就回问，不猜）

| 输入 | 来源 | 用途 |
|---|---|---|
| 需求说明 | `docs/pipeline/requirements.md` | 目标用户、场景、范围（做/不做）、约束、调研与借鉴结论 |
| 验收清单 | `acceptance_list` | 每条验收项都要能在界面上找到落点 |
| 设计标准 | 本手册 §5 与 WCAG 2.2 AA、Apple HIG、NN/g 10 Heuristics | 间距/字号/对比度/触控/状态/响应式/动效/ARIA 判定依据 |
| 设计系统 | 主题 token `--dsw-alias-*`；组件参考 `dsh-web-filebrowser-plugin/client.js` | 风格一致、深浅主题都可用 |
| 设备与主题 | Lead/PM 确认 | 桌面为主；是否要求 ≤768px 手机可用 |
| 上游结论 | `pipeline_status` + 阶段摘要 | 避免与已通过范围冲突 |

## 4. 产出与交付模板 v2

## 5. 专业设计质量标准（MUST / SHOULD）

> 分级：**MUST** = 不满足即不可提交/建议打回；**SHOULD** = 建议满足，缺失需在设计说明写理由。

### 5.1 九项硬标准（9 项 MUST，不可协商）

| # | 维度 | 硬标准 | 验收方式 |
|---|---|---|---|
| 1 | 间距 | **4/8px 体系**：基本单位 4px、主节奏 8px；间距取 4 的倍数（0/4/8/12/16/20/24/32…），禁止 6/7/9/10/11px 魔法数字 | grep 数值 + 对照 tokens 表 |
| 2 | 字号与行高 | 明确**字号阶梯** 12/14/16/20/24/32；正文**行高 ≥1.4**；字重 400/500/600/700 | tokens 表 + 渲染截图 |
| 3 | 颜色与对比度 | 颜色 token 化；正文**对比度 ≥4.5:1**，大字号（≥24px 或 ≥18.66px 粗体）**≥3:1**，非文本/焦点 ≥3:1；不得用颜色单独表意 | 对比度实测表（深浅主题各一组） |
| 4 | 触控目标 | 可点击区域 **≥44×44** CSS px（项目目标；建议 48×48）；指针密集桌面最低 24×24 + 间距 ≥8px，须声明例外 | 组件尺寸标注 + 实测 |
| 5 | 完整状态 | **八态状态矩阵**：默认 default / hover / focus / active / disabled / loading / empty / error 齐备；只读区至少 empty/loading/error/success；N/A 写理由 | 状态矩阵逐格检查 |
| 6 | 响应式 | 至少覆盖 **360 / 768 / 1280** 三档，写清断点与折叠行为；三档都能完成核心任务、无横向溢出 | 三档截图/渲染记录 |
| 7 | 动效 | 时长 **150–300ms** + easing；只动画 transform/opacity；必须支持 **prefers-reduced-motion** 降级，无闪烁 | 动效说明 + 降级验证 |
| 8 | 可访问性 | **键盘**可达、焦点可见（2px 环 + 2px offset，对比 ≥3:1）、**ARIA**/可读名称、图片 alt、浮层 Esc 关闭并归还焦点 | 键盘走查 + 读屏抽查 |
| 9 | 视觉一致性与层级 | 组件/术语/间距/圆角来自同一 token 与组件库；视觉层级 ≥3 级；一屏 **1 个主行动**、次行动 ≤2；同功能同名、同状态同色 | 评审清单 + 设计说明自检 |

- **must 一票否决**：对比度、触控、关键状态、键盘/焦点、调研、迭代任一失败 → 不可提交，不论自评分多高。
- SHOULD：48×48 触控、2 轮以上迭代、全组件八态、深浅主题双跑、动效编排；复用既有 `--dsw-alias-*` 优先于新增值。

### 5.2 八态状态矩阵（MUST）

八态 = 默认 default / hover / focus / active / disabled / loading / empty / error；N/A 必须写理由。

| 组件 | default | hover | focus | active | disabled | loading | empty | error |
|---|---|---|---|---|---|---|---|---|
| 主按钮 |  |  |  |  |  |  | N/A |  |
| 次按钮 |  |  |  |  |  |  | N/A |  |
| 图标按钮 |  |  |  |  |  |  | N/A |  |
| 输入框 |  |  |  |  |  |  |  |  |
| 开关/勾选 |  |  |  |  |  |  | N/A |  |
| 列表/表格 |  |  |  |  |  |  |  |  |
| 异步区块 | N/A | N/A | N/A | N/A | N/A |  |  |  |
| 弹层/Toast |  |  |  |  |  |  | N/A |  |

- 每格写「视觉（token/尺寸）+ 文案 + 交互 + 验收方式」；找不到 N/A 理由时按缺失处理。
- focus / disabled / loading / empty / error 五态是 MUST；缺任一 → 自评「反馈」维度 ≤2，不得提交。
- 页面级状态（整页空/加载/错误/无权限）与组件级状态分开写，不能互相替代。

### 5.3 Nielsen 10 启发式走查（MUST）

| # | 启发式 | 检查问题（通过标准） |
|---|---|---|
| 1 | 系统状态可见 | 用户随时知道「现在到哪、下一步是什么」；异步操作 100ms 内有反馈 |
| 2 | 贴合真实世界 | 用业务语言而非内部字段名；中英文术语一致 |
| 3 | 用户可控与自由 | 危险操作可取消/二次确认；浮层可 Esc；不强制长流程 |
| 4 | 一致性与标准 | 同功能同名、同状态同色、同间距同值；复用 token/组件 |
| 5 | 错误预防 | 约束在操作前可见；不可逆操作有确认；禁用态有原因 |
| 6 | 识别优于回忆 | 关键信息在当前屏可见；不用记 ID 或上一页 |
| 7 | 灵活高效 | 熟手可少点击；新手有路径；快捷键不冲突 |
| 8 | 美学与极简 | 信息分层；一屏一个主行动；无冗余装饰 |
| 9 | 错误识别/诊断/恢复 | 错误说明「什么错、为什么、怎么修」；不丢输入 |
| 10 | 帮助与文档 | 字段说明/hint/title 在需要处出现；不靠外部文档才能完成任务 |

- 每个设计阶段至少做一次走查，把发现/严重度/修正写进设计说明（模板 §9 迭代记录）。

### 5.4 五维自检评分 rubric（MUST）

| 维度 | 4 分（良好，可提交）锚点 | 证据 |
|---|---|---|
| 视觉层级 | 层级清晰、一屏一个主行动、扫视路径明确 | 截图 + 层级说明 |
| 清晰度 | 文案准确、状态可读、术语一致、无歧义 | 文案对照表 |
| 一致性 | token/组件/术语统一，深浅主题一致 | tokens 表 + 截图 |
| 反馈 | 八态关键项齐备，错误可恢复，防重复提交 | 状态矩阵 + 交互说明 |
| 可访问性 | 对比度/焦点/ARIA/触控/降级全部达标 | 实测表 + 键盘走查 |

- 每维 **0–5**（0.5 为最小刻度）；**每维 ≥3 且五维均分 ≥4.0** 才可提交，**≥4.5** 为优秀。
- 评分必须附**证据**（文件/截图/对比度数值/grep 结果）；无证据的分数降一档，关键项按 0 计。
- **must 一票否决**（§5.1 所列）失败时，无论均分高低都不可提交；自评分不能替代 Owner 评审，acceptance 会按同一 rubric 抽查。

### 5.5 迭代协议：渲染 → 检查 → 修正（MUST ≥1 轮）

- 未渲染、未按标准复检的稿不得提交；纯文字描述不算设计交付。
- 轮次建议：R1 结构与层级（1280）→ R2 状态/颜色/对比度（浅色+深色）→ R3 边界与无障碍（360/768 + 200% 缩放 + 键盘）。
- 记录格式（写入设计说明 §9）：

| 轮次 | 触发（渲染/走查） | 发现（对照标准条目） | 修正 | 证据路径 | 复评分 |
|---|---|---|---|---|---|
| R1 | 1280 渲染 |  |  | `design/xxx-r1.png` |  |
| R2 | 深色/关键态 |  |  | `design/xxx-r2.png` |  |

- 渲染工具：浏览器打开 SVG/HTML，或用 Node `sharp`/`rsvg-convert` 转 PNG；**无渲染工具时必须写「未渲染」及原因**，不得冒充已渲染。
- 无 UI 变更（如只改文档/提示词）仍需渲染交付物 + 记录检查与修正，并书面说明「无页面变更」及原因。

### 5.6 MUST 最小集（10 条，小需求 10 分钟自检）

1. 调研 ≥2 来源（URL + 访问日期 + 关键结论）。
2. 间距只用 4 的倍数（4/8px 体系）。
3. 字号出自阶梯，正文行高 ≥1.4。
4. 正文对比度 ≥4.5:1、大字号 ≥3:1（记录计算值）。
5. 控件边界/焦点环非文本对比 ≥3:1。
6. 触控目标 ≥44×44（指针密集桌面 ≥24×24 + 8px 间距并说明）。
7. focus / disabled / loading / empty / error 五态齐备。
8. 360 / 768 / 1280 三档不溢出、可完成核心任务。
9. 150–300ms 动效 + `prefers-reduced-motion` 降级。
10. 键盘可达 + 焦点可见 + ARIA/可读名称 + 一轮「渲染→检查→修正」。

## 6. SOP（design 阶段按顺序执行）

1. `pipeline_status` 确认 design 为 active；`pipeline_stage_prompt({stageId:'design'})` 取完整角色要求；读需求 + 验收清单 + 上游摘要。
2. 列页面/组件/状态清单；缺信息一次性问 Lead，不空等。
3. **调研（§5 前置）**：用 `web_search` / `web_fetch` 检索 ≥2 个同类产品/设计系统，写来源表 + 借鉴决策表；无网络标 `blocked`，不伪造。
4. 查设计系统：先在 `client.js` 找可复用组件与 `--dsw-alias-*` token；确定 4/8px 间距与字号阶梯，先写 tokens 与八态状态矩阵。
5. 出高保真稿：关键页面/状态各至少 1 张（PNG/JPG/SVG 或可预览 HTML），保存到 `docs/pipeline/design/`；需求涉及 UI 时不得只写文字描述。
6. **自检（§5）**：对比度（正文 4.5:1、大字 3:1、非文本 3:1）、44×44、360/768/1280、键盘/ARIA、prefers-reduced-motion、Nielsen 10 走查。
7. **迭代**：渲染 → 检查 → 修正，至少 1 轮，记录前后差异与证据（§5.5）。
8. **五维自检评分**（§5.4）：每维 ≥3、均分 ≥4，must 项一票否决；评分附证据。
9. 写交接段（§8）；`pipeline_submit_stage({stageId:'design', summary, artifacts:[{path:'docs/pipeline/design.md',label:'设计说明'},{path:'docs/pipeline/design/shot-home.png',label:'首页截图'},…]})`，截图逐张列入 artifacts。
10. **停下等 Owner 审批**，不进入 development；被打回按备注逐条改 → 版本号 +1 → 重新提交；连续两次打回交 Lead 缩范围/换方案。

## 7. 设计评审清单（提交前逐项勾）

- [ ] 调研 ≥2 来源：URL + 访问日期 + 关键结论 + 采用/不采用理由。
- [ ] 间距只用 4 的倍数（4/8px 体系），无 6/7/9/10px 魔法数字。
- [ ] 字号来自阶梯（12/14/16/20/24/32），正文行高 ≥1.4。
- [ ] 颜色全部 token 化；正文对比度 ≥4.5:1，大字号 ≥3:1，非文本/焦点 ≥3:1（记录实测值）。
- [ ] 可点击区域 ≥44×44（或 24×24 + 8px 间距并说明）；危险操作不紧邻常规操作。
- [ ] 八态状态矩阵齐备（默认/hover/focus/active/disabled/loading/empty/error），N/A 有理由。
- [ ] 360 / 768 / 1280 三档均可完成核心任务，无溢出/截断。
- [ ] 动效 150–300ms，支持 prefers-reduced-motion，无闪烁。
- [ ] 键盘可达、焦点可见；ARIA/可读名称；不用颜色单独表意。
- [ ] Nielsen 10 启发式走查完成，问题有修正记录。
- [ ] 高保真稿覆盖关键页面与关键状态（非纯文字）。
- [ ] 自检评分五维均 ≥3、均分 ≥4；must 项通过；评分有证据。
- [ ] 至少一轮「渲染→检查→修正」记录（渲染环境/证据/复评分）。
- [ ] 与现有设计系统一致（token/组件/术语/圆角）；深浅主题都过。
- [ ] 给开发/测试的交接段完整；未决问题有负责人与假设。

## 8. 交接

**给开发**：页面/组件与状态对照表；交互细节（点击、悬停、键盘、加载时序、防重复、滚动/固定）；边界条件（无权限、超长、断网、并发）；每条验收项 → 页面/控件/文案；明确「可自由调整」与「不可偏离」。v1.2.73 起另附：设计 tokens（间距/字号/颜色/动效）、八态矩阵、响应式断点、键盘/ARIA 行为、错误恢复与防重复要求。

**给测试**：每页四态视觉基线、移动端断点、主题切换、键盘操作、错误文案；需要的数据条件（空/慢请求/500/超时/超长）与复测步骤；验收项到截图的映射。v1.2.73 起另附：每状态视觉基线、对比度实测值、三档断点、深浅主题、键盘/读屏抽查、reduced-motion 验证。

## 9. 常见失败模式

| 失败 | 后果 | 规避 |
|---|---|---|
| 只画 happy path | 空/错/加载态无人设计，复测才发现 | 八态状态矩阵逐格检查 |
| 设计不可实现 | 开发临时拼或加依赖，偏离方案 | 先查现有组件与 token |
| 与设计系统冲突 | 硬编码色值/间距，深浅主题花 | 只用 `--dsw-alias-*` token |
| 只有一句话/无资源 | 开发猜、测试无基线 | 模板 + 高保真稿 + 交接段 |
| 范围漂移 | 设计变需求变更，闸门反复 | 记「未决问题」交 PM 决策 |
| 未调研就出稿 | 方案无依据、返工 | 来源表 + 借鉴决策表 |
| 只画 happy path/缺八态 | 开发临时补、测试无基线 | 状态矩阵逐格检查（含 N/A 理由） |
| 字号/间距随手值 | 不一致、难维护 | 4/8px 体系 + 字号阶梯 |
| 对比度不达标 | 低视力不可读、验收打回 | 对比度实测表 + must 一票否决 |
| 未渲染/未迭代 | 溢出与断点问题到开发才暴露 | 「渲染→检查→修正」记录 + 证据 |
